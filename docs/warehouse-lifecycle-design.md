# 实验室物品全生命周期出入库管理系统 · 设计方案

> 适用范围：在现有「万州职教中心实验室管理」小程序（腾讯云开发 + 腾讯文档 8 表 + 云函数防腐层 `docsProxy/tencentdocs.js`）之上扩展。
> 目标：补齐「二维码生成 ↔ 扫码操作」闭环，使入库可生成专属码 / 可扫自带条码建档，出库可扫码秒级调取并完成扣减，库存实时联动、流水可追溯。

---

## 0. 现状与缺口（改造基线）

| 能力 | 现状 | 缺口 |
|---|---|---|
| 扫码 | `wx.scanCode` 仅作**查询入口**，跳 detail 页 | 扫码不能直接出入库 |
| 二维码 | 无生成功能（snapshot 仅返回 `qr = 物品ID` 占位字段） | 实物码需外部工具贴 |
| 条码 | `scanCode` 本身支持条码，但解析后只当 ID 用 | 无「自带条码 ↔ 物品」绑定关系 |
| 入库 | io 页手动 picker 选耗材 + 填数量 | 新建物品、生成码、扫条码建档均无 |
| 出库 | io 页选物品 + 方向 + 数量 | 不能「扫一下即出库」 |
| 绑定关系 | 仅 materials/tools 各自 ID | 缺「一物多码 / 码→物」解析中枢 |

**设计原则**：保持「库存写入单一职责在云函数 `io` action」；新增「编码解析中枢」与「编码绑定表」；前端负责二维码**绘制**（canvas），后端只负责生成 ID 与维护绑定。

---

## 1. 整体架构

```
[物理层]  自生成二维码 ──┐
         物品自带条码  ──┼─→ wx.scanCode(result)
                          │
[交互层]  小程序页面（入库页 / 出库页 / 详情页）
          ├─ 扫码 → resolveCode 解析
          ├─ canvas 绘制二维码（入库成功后）
          └─ 表单录入 品名/规格/数量/位置
                          │
[数据层]  云函数 docsProxy（防腐层）
          ├─ resolveCode / bindCode / addMaterial(扩展) / io(扩展)
          └─ 腾讯文档 9 表：materials / tools / codes(新增) / stock_io / requisitions / borrow / access / logs / users
```

## 2. 编码体系与绑定模型

### 2.1 两种码
- **自生成二维码（QR）**：系统新建物品时生成，内容=`ITEM:{物品ID}`（如 `ITEM:M001`）。短、解析快、不依赖网络。
- **物品自带条码（BARCODE）**：厂商印刷的条形码，原始值直接入库（如 `6901234567890`）。

### 2.2 码内容规范
| 类型 | 内容 | 解析方式 |
|---|---|---|
| QR | 纯文本 `ITEM:M001` | 前缀 `ITEM:` 直取 ID |
| BARCODE | 原始数字/字符 | 查 `codes` 表反查物品ID |

### 2.3 绑定关系（核心）
- **一物可多码**：同一耗材可同时绑「自生成二维码」+「自带条码」。
- **一码只绑一物**：`codes.value` 全局唯一，重复绑定拦截。
- 解析中枢 `resolveCode`：先判 `ITEM:` 前缀；否则查 `codes` 表；未命中则进入建档流程。

### 3.2 编码绑定表 `codes`（**新增核心表**）
| 中文列名 | 键 | 类型 | 说明 |
|---|---|---|---|
| 编码ID | `id` | 自动编号 `CD-####` | 主键 |
| 物品ID | `itemId` | 文本 | 关联 `materials.id` 或 `tools.id`（建议带前缀 M/T 区分） |
| 关联类型 | `kind` | 单选(material/tool) | |

| 编码类型 | `type` | 单选(QR/条码) | |

> **唯一约束**：建码前先查 `value` 是否已存在，命中则提示「该码已绑定 {物品ID}」，避免重复建档。

### 3.4 工具 `tools` / 申请 `requisitions` / 借还 `borrow` / 门禁 `access` / 日志 `logs` / 用户 `users`

## 4. 操作流程设计

### 4.1 入库 · 新物品生成专属二维码
```
① 入库页 →「新建物品 + 生成码」
② 填表单：品名 / 规格 / 单位 / 初始数量 / 存放位置
③ 提交 → 云函数 addMaterial
        ├─ 建 materials 主档（自动编号 RQ-...）
        └─ 写 codes 一条 { itemId, type=QR, value='ITEM:RQ-...' }
④ 返回 物品ID → 前端 canvas 绘制二维码 → 长按保存 / 打印贴签
```
> 后端只需保证 ID 生成与写码；二维码图片由前端 canvas 现绘，无需服务端出图。

### 4.2 入库 · 扫描物品自带条码建档
```
① 入库页 →「扫条码建档」
② wx.scanCode → 原始值 R
③ resolveCode(R) 未命中
④ 自动打开建档表单，条码值预填到 codes.value(type=条码)
⑤ 填品名/规格/数量/位置 → 提交
        ├─ 建 materials 主档
        └─ 写 codes { type=条码, value=R }
⑥ （可选）同时补打一张自生成二维码贴签
```

### 4.3 出库 · 扫码快速调取并出库
```
① 出库页 / 详情页 →「扫码出库」
② wx.scanCode → R
③ resolveCode(R)
        ├─ 命中 → 取得 itemId + 物品档案
        └─ 未命中 → 提示「未登记物品，请先入库」
④ 展示档案卡片：名称 / 规格 / 当前库存 / 位置
⑤ 输入出库数量（前端校验 ≤ 当前库存）
⑥ 确认 → io action（type=out, 带 code=R）
        ├─ withWriteLock 串行
        ├─ withWriteIdem 5s 幂等（防双发双倍扣减）
        ├─ 更新 materials.stock
        ├─ 写 stock_io（方向=出库, 关联编码=R）
        └─ 写 logs
⑦ 库存实时刷新、流水可查
```

### 4.4 编码解析流程 `resolveCode`
```
输入 R
 ├─ R 以 'ITEM:' 开头 → 截取 → itemId，直查主档
 ├─ 否则 → SELECT codes WHERE value = R
 │         ├─ 命中 → { kind, itemId } → 查主档
 │         └─ 未命中 → 返回 { found:false, raw:R } → 触发建档
 └─ 返回 { kind, itemId, item }
```

### 4.5 库存实时更新
- **唯一写入点**：云函数 `io` action（已含 `withWriteLock` 串行 + `withWriteIdem` 5s 幂等窗口）。
- 前端：列表/详情 `onShow` + 上拉刷新拉取，出库后 `setData` 即时回显。

### 4.6 历史查询
- `stock_io` 按 物品ID / 方向 / 操作人 / 时间区间 过滤（现有 `listStockIO` 扩展筛选参数）。
- inventory / usage 页已有基础，增强时间区间与编码维度即可。

## 5. 状态机与并发安全

| 风险 | 对策（复用既有能力） |
|---|---|
| 出库双发 → 双倍扣减 | `withWriteIdem(key=[io,actor,itemId,type,qty])` 5s 窗口复用首次结果 |
| 库存读-算-写竞态 | `withWriteLock` 串行化所有写 |
| 一码绑多物 | `codes.value` 唯一约束 + 建前查重 |
| 弱网重复提交 | 幂等窗口 + 前端 busy 守卫双保险 |
| 编码解析漂移 | `resolveCode` 单点，三端（前端/云mock/生产）对齐 |

## 6. 云函数接口设计（action 扩展）

| action | 入参 | 返回 | 说明 |
|---|---|---|---|
| `resolveCode` | `{ code }` | `{ found, kind, itemId, item }` | 编码解析中枢（新增） |
| `bindCode` | `{ itemId, kind, value, type }` | `{ code }` | 绑定码（新增，含查重） |
| `addMaterial` | `{ name, spec, unit, qty, loc, ... }` | `{ id, qr:'ITEM:...' }` | 扩展：建档同时写 codes(QR) |
| `io` | `{ matId, type, qty, actor, code? }` | `{ no }` | 扩展：带 `code` 写流水关联 |
| `listStockIO` | `{ itemId?, dir?, from?, to? }` | 流水列表 | 扩展筛选 |

> QR 内容（`ITEM:M001`）由后端在 `addMaterial` 返回，前端 canvas 据此绘制。

## 7. 前端落地要点

1. **二维码绘制**：详情页 / 入库成功页用 `wx.createCanvasContext` + 轻量库（如 weapp-qrcode）绘制 `ITEM:{id}`，支持长按保存、打印。
2. **入库页改造**：新增「新建物品+生成码」「扫条码建档」两个入口，表单提交后展示二维码。
3. **出库页改造**：新增「扫码出库」按钮，扫后弹出数量录入 → 调 `io(out)`。
4. **详情页补齐**（解决此前 Gap）：教师扫耗材时吸底条增加「入库登记 / 出库登记」入口，带 `?id=&dir=` 跳 io 页自动预选。
5. **解析失败兜底**：`resolveCode` 未命中时引导建档而非静默。

## 9. 风险与对策

- **历史账目偏差**：早期「删流水不调库存」使期初账不可精确追溯，正式启用前建议做一次实物盘点重置。
- **多实例幂等漏网**：`withWriteIdem` 为实例内存态，跨实例极小概率漏网，属可接受兜底（业务量单实例可覆盖）。
- **条码脏值**：自带条码可能因磨损/重复导致解析错误，建议建档时人工核对品名。
- **凭证续期**：腾讯文档 access_token 约 27 天到期，需提前续（运维项，非本设计范围）。
