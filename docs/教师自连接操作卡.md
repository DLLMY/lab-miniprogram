# 教师自连接 WorkBuddy 操作卡

> 一句话：每位老师**自己**在手机小程序里生成一把「只属于自己工号」的密钥，填进自己电脑上的 WorkBuddy，就能用自然语言查/处理实训室系统的信息——**权限和你微信端完全一致**，动不了别人的数据，也动不了管理员功能。

---

## 一、你能用它做什么

| 类型 | 能做的例子 | 是否需要确认 |
|------|-----------|------------|
| 🔍 只读查询（直接出结果） | "查一下 A 柜还有多少焊锡丝" / "列出我名下待处理报修" / "本周耗材出入库趋势" / "B 实训室逾期巡检有几条" | 不需要 |
| ✏️ 受控写操作 | "我要提交 A 实训室示波器报修" / "领用 2 卷电工胶带" / "登记工具借出" | **需要二次确认**（系统先回操作摘要+确认码，你说"确认"才真写） |
| 🔔 每日主动推送 | 管理员已配置「实训室每日预警推送」自动化，早上 8:20 自动汇总低库存/逾期巡检/待审批（只读提醒，绝不自动改数据） | 自动 |

> ⚠️ 写操作一律走"先确认后执行"，避免误改。这和微信里点按钮提交是同一套权限闸门。

## 二、准备清单（开始前确认）

- [ ] 你的实训室小程序账号已绑定工号，且角色为「教师」（或管理员）。
- [ ] 管理员已把 **docsProxy 云函数重新部署上线**，并给你一个全校共用的 **HTTP 触发地址**（形如 `https://xxx.apigw.tencentcs.com/...`）。
- [ ] 你自己的电脑上已安装 **WorkBuddy**（本机一份，和别人的互不干扰）。
- [ ] 电脑上装有 **Node.js ≥ 16**（验证：命令行输入 `node -v` 能看到版本号）。

> 若第 2 条还没拿到地址，先找管理员（邓老师）要。**密钥各填各的，任何人拿不到别人的身份。**

## 三、四步自连接（全程自己完成）

### 步骤 1 · 小程序里生成你的个人密钥

1. 打开「实训室管理」微信小程序 → 底部「我的」。
2. 找到 **「个人机器人密钥」** 卡片（在"我的申请"上方）。
3. 点 **「生成我的密钥」**（若已生成过则显示「重置密钥 / 吊销密钥」）。
4. 系统弹出**仅显示一次的明文密钥**，例如：

   ```
   ┌──────────────────────────────────────────────┐
   │  lab_rk_9f3a...c71e（示例，实际更长）          │
   │  ⚠ 密钥明文仅显示这一次，请立即复制保存。      │
   │  [ 复制密钥 ]                                  │
   └──────────────────────────────────────────────┘
   ```

5. 立刻点 **「复制密钥」**，先粘贴到手机备忘录或微信"文件传输助手"里临时存着（下一步要填进电脑）。
   > 关闭后无法再查看，只能「重置」生成新的。

### 步骤 2 · 本机装好 WorkBuddy + Node

- 装 WorkBuddy（桌面客户端）。
- 装 Node：到 nodejs.org 下载 LTS 版安装，装完打开命令行输入 `node -v`，能看到 `v16.x / v18.x / v20.x` 即成功。

### 步骤 3 · 配置连接器（填两行）

1. 打开 WorkBuddy 本机配置文件 `mcp.json`（位置见下方"模板"说明）。
2. 在 `mcpServers` 下加入下面这一项，**只改两个值**：
   - `DOCS_PROXY_HTTP_URL` → 管理员给的全校共用地址
   - `DOCS_PROXY_ROBOT_KEY` → **你自己在步骤 1 复制的那把个人密钥**

### 步骤 4 · 信任启用，开始对话

1. 在 WorkBuddy 左侧「连接器 / 自定义 MCP」里找到 `lab-docs-proxy`，点 **信任启用**。
2. 新建一个对话，直接说人话即可，例如：

   > 「查一下 M001 物料的当前库存和预警线」
   >
   > 「列出我名下所有待处理报修」
   >
   > 「B 实训室本周有没有逾期巡检」

## 四、mcp.json 完整模板

> 文件通常位于：WorkBuddy 用户目录下的 `mcp.json`（可在 WorkBuddy 设置里打开"打开配置文件"）。
> 若文件已存在，只需把 `lab-docs-proxy` 这段**合并进已有的 `mcpServers` 对象**，不要覆盖其他内容。

```json
{
  "mcpServers": {
    "lab-docs-proxy": {
      "command": "node",
      "args": ["C:/你的路径/lab-miniprogram/mcp/docs-proxy-server.js"],
      "env": {
        "DOCS_PROXY_HTTP_URL": "https://这里填管理员给的全校共用HTTP触发地址",
        "DOCS_PROXY_ROBOT_KEY": "这里填你自己在小程序生成的个人密钥"
      }
    }
  }
}
```

字段说明：

| 字段 | 填什么 | 注意 |
|------|--------|------|
| `command` | `node` | 系统已装 Node 即可 |
| `args[0]` | 连接器脚本**绝对路径** | 指向你本机 `lab-miniprogram/mcp/docs-proxy-server.js` |
| `DOCS_PROXY_HTTP_URL` | 全校共用地址 | 所有人填**同一个** |
| `DOCS_PROXY_ROBOT_KEY` | **你自己的**个人密钥 | 每人填**各人的**，切勿填管理员的超级钥匙 |

## 五、示例对话（照着说就行）

### 例 1 · 查询（直接出结果）

**你**：查一下 A 柜焊锡丝还剩多少，预警线是多少？
**WorkBuddy**：返回物料详情（名称/库存/预警线/位置）。

**你**：列出我名下待处理报修。
**WorkBuddy**：返回你提交的、状态为"待处理"的报修列表。

### 例 2 · 写操作（带确认门）

**你**：帮我提交 A 实训室 3 号示波器报修，故障是 CH1 无波形。
**WorkBuddy**：

```
⚠ 需确认：以【你的姓名(你的工号)】身份提交报修
   实训室：A 实训室
   设备：3 号示波器
   故障：CH1 无波形
[确认码 C7f3a2] 请回复「确认执行」或调用 lab_confirm 完成。
```

**你**：确认执行
**WorkBuddy**：✅ 已提交报修 R00x（操作人 你的工号）。

> 如果你发现填错，直接不回复"确认"即可，**什么都不发生**；或说"取消"。

## 六、安全须知（务必看）

1. 🔑 **密钥只显示一次**：生成/重置后明文仅出现一次，关闭即不可见，只能再次「重置」换新。
2. 🚫 **不要分享你的密钥**给任何人，包括管理员。它等于"以你身份登录系统"的钥匙。
3. 🔄 **离职/换电脑**：在「我的 → 个人机器人密钥」点「吊销密钥」，旧密钥立刻失效。
4. 🛡️ **权限同构**：你通过 WorkBuddy 能看/能改的，和你微信端完全一样；越权操作会被后端拒绝（返回权限不足）。
5. ⚠️ **永远不要把管理员的超级钥匙（ROBOT_KEY）填进自己的 mcp.json**——那是给系统应急用的，不是给教师的。

## 七、常见问题 FAQ

**Q：提示"未配置 DOCS_PROXY_HTTP_URL"？**
A：步骤 3 的 `mcp.json` 里 `env` 没填或路径错。检查地址是否完整（含 `https://`）、连接器是否重启生效。

**Q：提示"机器人身份校验失败 / 401"？**
A：个人密钥填错或已吊销。回小程序「我的」点「重置密钥」，复制新密钥重填 `DOCS_PROXY_ROBOT_KEY`，重启 WorkBuddy 连接器。

**Q：写操作一直不执行？**
A：写操作必须"确认"才执行。看到 `[确认码 Cxxx]` 后，回复「确认执行」或让 WorkBuddy 调用 `lab_confirm`。

**Q：普通教师能收到每日预警推送吗？**
A：每日推送是管理员配置的全局自动化（只读提醒），全校可见。教师个人也可在自己的 WorkBuddy 里配置同样的自动化，用**自己的密钥**拉取"与我相关"的视角。

**Q：换电脑了怎么办？**
A：新电脑装好 WorkBuddy+Node，重新走步骤 3 填配置即可（密钥不变，从备忘录粘贴；若忘了就小程序重置一把新的）。

## 八、管理员补充（给邓老师）

- **全校共用**同一个 `DOCS_PROXY_HTTP_URL`（CloudBase HTTP 触发地址）；教师各自填自己的个人密钥。
- 每日预警推送自动化已建（名称「实训室每日预警推送」，每天 08:20，ACTIVE），调用 `lab_query(action=alerts)`，硬性约束只汇总不写。
- 教师密钥体系：后端 `clouddb.js`/`tencentdocs.js` 的 `findUserByRobotKey`/`setRobotKey` + `users.robotKeyHash` 字段；`index.js` robot 通道按密钥哈希反查工号、以教师本人身份执行；`ROBOT_KEY` 仅作管理员应急超级通道，绝不发给教师。
- 详细机制与扩展（L2/L3/L4 路线）见 `docs/workbuddy-integration.md` 与 `docs/workbuddy-conversation-design.md`。
