# 数据域隔离设计（方案 C · 完整行级隔离）

> 2026-11-15 落地。补齐原有系统缺失的「数据域隔离」：原有 RBAC 只解决
> *谁能管理哪些账号*，本方案解决 *谁能看到 / 改动哪些业务数据*。

## 一、需求与结论

| 诉求 | 改造前 | 改造后 |
|---|---|---|
| 老师对应班级 | `users.cls` 有列但无约束力，老师账号班级为空 | 新增 `users.managedClasses`（可多班），由每学期《教师工作量安排》批量导入（见第八节） |
| 学生 / 班级管理员对应班级 | `users.cls` 有列但无约束力 | 每班 2 个共享申请账号绑定本班；写入流水时自动继承 `cls`，并在列表显示 |
| 老师 ↔ 老师 隔离 | ❌ 全通 | ✅ 仅可见 / 可改本人带班的流水 |
| 班级 ↔ 班级 隔离 | ❌ 业务表无班级列 | ✅ 7 张流水表按 `cls` 行级隔离 |

## 二、关键设计决策（如与预期不符，一句话即可调整）

| # | 决策点 | 采用方案 | 理由 |
|---|---|---|---|
| 1 | 老师带班字段 | 新增 `managedClasses`（逗号分隔多班），`cls` 保留为主班 / 学生班级 | 支持一带多班，兼容存量 `cls` 数据 |
| 2 | 主数据是否隔离 | `materials / tools / labs / users` **全局共享，不隔离** | 老师必须能看到全部耗材工具才能领用；隔离会让系统不可用 |
| 3 | 流水是否隔离 | `requisitions / borrow / stock_io / access / logs / repairs / inspections` 按 `cls` 隔离 | 这些才是需要班级边界的业务数据 |
| 4 | `super` / `admin` | 全通，不注入任何过滤 | 管理员全权，且保证改造对现有账号零影响 |
| 5 | `teacher` | 仅 `cls ∈ 带班列表` 或 `cls` 为空（公共资源）的流水；跨班写返回 403 | 各管各班 |
| 6 | `student` | 仅本人产生的流水（按各表归属人字段），主数据全通 | 维持并强化现有 `listMine` 语义，最严格 |
| 7 | 空 `cls` 数据 | 视为**公共资源**，所有教师可见 | 管理员 / 超管预置或产生的记录不带班级，否则老师将看不到 |
| 8 | 空带班列表的老师 | 只能看到公共资源与本人记录 | fail-safe，不误放行 |

## 三、隔离规则矩阵

| 角色 | 主数据（耗材/工具/实训室/用户） | 流水（领用/借出/出入库/门禁/日志/报修/巡检） | 跨班写 |
|---|---|---|---|
| 未登录 | 门控按现有规则 | 门控按现有规则 | — |
| `super` | 全部 | 全部 | 允许 |
| `admin` | 全部 | 全部 | 允许 |
| `teacher` | 全部（用户列表仅本班学生） | 本班 + 公共资源 | **403 拒绝** |
| `student` | 全部（用户列表仅自己） | 仅本人 | 403 拒绝 |

## 四、技术实现

### 单一收敛点（避免改 60+ 业务函数）

两套适配器（`clouddb.js` / `tencentdocs.js`）的**唯一读写入口**是
`getRecords / addRecord / updateRecord / deleteRecordByIds`。隔离逻辑全部收敛到这四处：

| 入口 | 注入内容 |
|---|---|
| `getRecords(sheetKey, filterFn, opts)` | 业务 `filterFn` 之后追加 `rowVisible()` 行过滤 |
| `addRecord(sheetKey, fieldsMap)` | 流水表自动补写归属列 `cls`（取当前 scope 的 `ownerCls`） |
| `updateRecord(sheetKey, id, fields)` | 跨班写守卫：读原记录 → `canWriteRow()`，拒绝抛 `ScopeDeniedError` |
| `deleteRecordByIds(sheetKey, ids)` | 同上 |

**好处**：`usage()` 报表、`exportData()`、`snapshot()` 等内部都走 `getRecords`，
过滤在最底层生效 → **报表聚合口径天然正确**，不会出现「先算全量再删行」的统计错误。

### 请求级上下文（并发安全）

`data-scope.js` 导出 `AsyncLocalStorage` 单例：
- `prodHandler` 解析出 `me` 后，用 `runWithScope(scopeOf(me), () => 处理请求)` 包裹整个请求；
- 适配器从 `currentScope()` 读取，**不用模块级全局变量**，云函数并发请求互不串味；
- 业务函数签名一律不变 → 契约零漂移。

### fail-safe 降级

- 未登录 / `super` / `admin` → `scope.full = true`，**完全不注入过滤**，行为与改造前逐字节一致；
- `async_hooks` 不可用导致 `currentScope()` 为 `null` 时同样放行（登录等公开接口不受影响）；
- 只有 `teacher` / `student` 登录后才触发新逻辑 → 最小风险增量，可随时回退。

### 四套实现同步

| 实现 | 处理方式 |
|---|---|
| `clouddb.js`（线上真实后端，当前启用） | **完整实现**，归属列 `cls`（英文 key）；读过滤 / 盖章 / 跨班写守卫 |
| `tencentdocs.js`（备用后端） | **完整实现**，归属列 `归属班级`（中文列名）；`buildValues` 对不存在的列自动跳过 → **未加列时自动退化为不隔离，不会破坏现有功能** |
| `index.js` 的 `prodHandler` | 用 `runWithScope` 包裹整个请求，`ScopeDeniedError` 在 `run()` 与 `main` catch 双重转 403 且**禁止回退链重试** |
| `index.js` 的 `mockHandler` / `utils/mock.js`（演示回退） | **有意不实现隔离**：演示模式刻意不做服务端鉴权、seed 全空、不接触真实数据；小程序端也无法 require 云函数目录。代码内已写明此处置。 |

> 隔离只作用于**真实数据路径**（cloud / tencent + prodHandler）。演示数据是离线兜底，
> 不含任何真实账号或流水，隔离它没有实际意义，反而会让演示数据「莫名消失」被误判为故障。

### 跨班写守卫

`updateRecord` / `deleteRecordByIds` 底层拦截 + `prodHandler` 对
`approve / cancelReq / reverseIO / updateRepair / updateInspection` 等高风险 action
做显式前置守卫，给出明确 403 文案而非含糊的「记录不存在」。

## 五、数据模型变更

```
users           + managedClasses   老师带班列表（逗号分隔，须用权威全称，如「2024级电气1班,2024级电气2班」）
users.cls                        班级管理员 / 学生的本班归属（同样是权威全称）
requisitions    + cls              归属班级
borrow          + cls
stock_io        + cls
access          + cls
logs            + cls
repairs         + cls
inspections     + cls
materials / tools / labs   不变（全局共享）
```

> 线上业务表在 2026-11-15 已清空，无历史数据迁移负担；`users` 体现共 64 行：
> 超级管理员 1 / 管理员 3 / 教师 18（`WT001–WT018`）/ 班级管理员 40 / 测试学生 2（详见第八节）。
> **班级无独立实体**，只是上述字段里的字符串；用户明确要求「班级不需要新页面」。
> 班级口径以学期主数据的 `classes` 数组为准（见 8.4），完整对照见账号清单 Excel「班级对照」表。
> 云库集合无需预建字段（schema-less）；腾讯文档后端若要启用隔离，
> 需在对应智能表格**手工新增「归属班级」「带班班级」两列**，否则自动退化为不隔离。

## 六、部署顺序（重要）

1. **数据先行（不改线上运行时）**：`node tools/import_teachers.js --term <学期> --apply`
   把教师账号（带班）与班级管理员账号（本班）写入 `users` 表。数据就位但**隔离尚未生效**，
   无需重新上传小程序代码包。
2. **云函数生效**：微信开发者工具「上传并部署 `docsProxy`」——这是行级隔离真正起作用的开关。
   ⚠️ 开发/体验/正式版共用同一云函数，部署会立即改变所有版本的运行时行为；
   审核期间若希望零变更，可等审核通过后再部署。此期间 `super` / `admin` 行为完全不变，
   `teacher` 仍按旧逻辑全通（只是账号多了带班字段，无副作用）。
3. **前端可选**：`pages/admin-users` 支持单账号编辑带班班级；批量维护一律用脚本，不必逐个手填。
   若要在手机上改带班，需重新上传开发版并提交一次新审核。
4. 老师无需重新登录（`scope` 每次请求实时计算）。
5. 回退：清空老师的 `managedClasses` → 该账号只看公共资源；
   或设置环境变量 `DATA_SCOPE=off` 全局关闭过滤（见 `data-scope.js` 开关）。

> 版本自检：`import_teachers.js` 会探测 `adminListUsers` 是否回显 `managedClasses`。
> 未回显即判定线上为旧版云函数，脚本自动用 SDK 直连云数据库补写带班字段并打印提示，
> 避免「账号建好了但带班没写进去」的静默失败。

## 八、每学期账号与带班更新（制度化流程）

> 班级与任课关系**每学期变动**，因此 `managedClasses` 不是一次性配置，而是学期主数据。
> 2026-11-15 首次导入 `2026-2027-1`：18 个教师账号 `WT001–WT018`、
> 20 个班级、40 个班级管理员账号，线上 `users` 共 64 行。

### 8.1 数据源与工具链

```
教职工通讯录.xlsx ─┐
                    ├─ tools/build_term_data.py ─→ tools/data/terms/<学期>.json
教师工作量安排.xls ─┘                                    │
                                                         └─ tools/import_teachers.js --apply ─→ 线上 users
```

| 文件 | 作用 |
|---|---|
| `tools/build_term_data.py` | 解析两份表 → 姓名/班级归一化、按姓名复用工号、生成教师账号 + 每班 2 个班级管理员账号 |
| `tools/data/terms/<学期>.json` | **学期主数据**：教师/班级管理员账号、教师→班级映射、班级权威清单、勘误记录、离任名单 |
| `tools/import_teachers.js` | `--term` 预览 / `--apply` 幂等写入 + 自动备份 + 只读对账；`--group all\|teachers\|classAdmins` |
| `tools/export_account_list.js` | 只读导出账号清单 Excel（账号清单 / 班级对照 / 使用说明 三张表） |

### 8.2 账号范围口径（首次已确认）

- 「电气教师」= **《电气教师工作安排》中实际授课的教师**，不是通讯录「电气信息部」部门全员。
  2026-2027-1 学期工作量表 19 人，含 5 位外部门兼课教师（机械汽修部 / 学前教育部 / 教务处），
  按「上该班课就管该班耗材」原则一并建号；排除已有超级管理员的本人后共 18 个账号。
- 通讯录只用于**姓名实名核对**与部门标注；部门内未排课的语文/数学/体育/行政人员不建号。
- 已有 `T001 / 邓老师 / super` 的本人**不重复建号**（super 全通，无需带班）。
- **班级管理员账号**：每个班级 2 个，供本班学生共用提交耗材申请，角色 `student`、
  `cls` 绑定本班。名字用简称（如 `24电气1班管理员1`），工号按用户给定锚点
  `24电气1班管理员1 → 2024dq101`（系统统一转大写 `2024DQ101`）推导：
  `<4位年份><专业缩写><1位班号><2位序号>`，专业缩写 电气 `dq` / 工业 `gy` /
  数控 `sk` / 无人机 `wr` / 五年制 `wn`。20 个班级的短码显式固化在
  `build_term_data.py` 的 `CLASS_CODE`，新班级由 `derive_class_code()` 兜底推导。

### 8.3 工号稳定规则（防止跨学期身份漂移）

- `WT###` 按**姓名永久绑定**，不是每学期按表内顺序重新编号；
- 重跑生成器传 `--prev <上期JSON>` 复用「姓名 → 工号」映射，**只有新增教师才追加号码**；
- 离任教师仅列入 `retired`，由管理员手动「停用」，**脚本绝不自动删除账号**（保留历史流水归属）；
- 导入按工号 upsert，编辑已存在账号必须带 `rid`，否则触发 409 重号守卫；
  `import_teachers.js` 会自动从快照取 `rid`，保证重跑幂等。

### 8.4 班级清单（无独立实体）

- 系统**没有班级表**；班级是 `users.cls` / `users.managedClasses` / 流水表 `cls` 中的字符串。
  「班级创建」即把班级名写入学期主数据并绑定到教师，不存在单独的班级实体或 CRUD。
- 学期 JSON 的 `classes` 数组是**唯一权威口径**。学生账号、班级管理员账号、
  教师 `managedClasses`、流水 `cls` 必须逐字使用同一字符串（含全角括号等原样字符，
  不做二次加工），否则匹配失败会出现「老师看不到本班数据」。
- ⚠️ **简称只用于账号名字，绝不用于存值**。例如账号名叫 `24电气1班管理员1`，
  但 `users.cls` 必须写 `2024级电气1班`；教师带班列表里同样是全称。
  早期测试学生号曾用简称 `24电气1`，已统一修正为全称。
- 完整「班级 ↔ 双管理员工号 ↔ 任课教师」对照见账号清单 Excel 的「班级对照」表。
- 源表笔误由生成器 `CLASS_FIX` 修正并记入 `corrections`：`202025级数控班 → 2025级数控班`。
  用户 2026-11-15 确认「**吴逸锋**」是正确写法，通讯录里的「吴逸峰」仅作查部门别名
  （`ROSTER_ALIAS`），**不得再自动改名**；`NAME_FIX` 保持为空。

### 8.5 每学期操作步骤

1. 取得新学期《教职工通讯录》与《教师工作量安排》；
2. `python tools/build_term_data.py --term <新学期> --roster <...> --workload <...> --prev tools/data/terms/<上期>.json`；
3. 核对预览：账号数、班级数、已应用勘误、`retired` 离任名单；
4. `node tools/import_teachers.js --term <新学期>` 先 dry-run；
5. `node tools/import_teachers.js --term <新学期> --apply` → 自动备份 + 写入 + 对账；
6. `node tools/export_account_list.js --term <新学期>` 导出账号清单，分发给各班主任核对；
7. 对 `retired` 名单在小程序「用户管理」手动停用；
8. 云函数已是新版时**无需重新部署**——`scope` 每次请求实时读 `managedClasses`，改动即时生效。

### 8.6 隐私与生效边界

- 学期 JSON、`账号清单_*.xlsx` 与 `tools/backup_users_*.json` 含真实姓名/工号，
  已加入 `.gitignore`，不得提交仓库；`tools/` 整目录在 `packOptions.ignore` 中，
  也不会进小程序代码包。
- **数据就位 ≠ 隔离生效**：旧版云函数不认识 `managedClasses`，脚本会用 SDK 直连数据库补写，
  但行级过滤只有部署新版 `docsProxy` 后才真正起作用（见第六节）。
- 已知边界：老师带多个班时，其**新建流水**默认归属 `managedClasses` 的第一个班
  （`scopeOf().ownerCls`）；学生 / 班级管理员提交的流水按其 `cls` 归属，口径准确；
  审批产生的流水由 `overrideOwnerCls()` 继承原申请班级。
  用户明确要求「流水显示班级即可」，因此**不新增班级选择表单**（见第九节）；
  若将来要精确到「老师为哪个班领用」，需在业务表单增加「适用班级」下拉并显式传 `cls`。

### 8.7 归属正确性核查（每次导入后必跑）

两个只读脚本，用于回答「每个任课老师负责的班级是否正确归属」：

```bash
python tools/audit_term_mapping.py --term <学期> --dump    # 打印原始工作量表全部单元格
python tools/audit_term_mapping.py --term <学期> --check   # 原始表 vs 学期主数据逐人比对
node tools/audit_online_scope.js --term <学期>            # 线上 users 对账 + 班级覆盖 + 版本探测 + 隔离模拟
```

核查口径：

1. 教师 `managedClasses` 与工作量表教师行 D~H 列逐人一致（重复班级去重、笔误按 `CLASS_FIX` 修正）；
2. 所有班级名必须**逐字等于** `classes` 权威全称；学生 / 班级管理员的 `cls` 同样校验，
   否则 `rowVisible()` 会因字符串不等而静默漏数据；
3. 反查「班级 → 任课教师」，任一无任课教师的班级必须补录，否则该班申请只能由 admin/super 兜底；
4. 探测线上 `docsProxy` 是否回显 `managedClasses`（判断行级隔离是否已真正生效）；
5. 用线上真实带班值跑本地 `data-scope` 引擎模拟 `rowVisible()`，确认越权可见为 0。

> 超级管理员本人若也在工作量表中（如「邓磊」），由 `EXCLUDE_TEACHERS` 刻意排除，
> 不另建教师账号；super 为 `full=true` 全通，无需 `managedClasses`，
> 因此 `--check` 中该项显示差异属**预期**，不是归属错误。

## 九、审批链路与流水班级显示

### 9.1 审批链路（用户确认的期望）

```
本班学生 / 班级管理员账号（cls = 本班全称）
        │ 提交耗材申请 → requisitions.cls 自动继承本班
        ▼
任课教师（managedClasses 含本班）→ 部署新版云函数后只看得到本班 + 公共资源
        │ 审批通过 / 驳回（跨班申请直接 403）
        ▼
管理员 / 超级管理员 → full=true，可审批全部班级的申请（兜底）
```

- 「**优先其上课教师审批**」由**可见性**实现：任课教师看得到本班申请，
  管理员看得到全部。当前系统**没有强制审批顺序**（不存在「必须先由教师审批」的状态机）；
  若需要强制顺序，要改审批链路，属于后续增强。
- 「**管理员可以审批所有耗材申请**」由 `admin` / `super` 的 `full=true` 全通规则保证，
  与改造前行为一致，无需额外代码。

### 9.2 流水显示班级（用户要求，已实现）

- **后端**：两套适配器的 7 个 `norm*()` 归一化函数与 `listStockIO / listLogs / listAccess`
  的 rows 都补 `cls: ds.readCls(f)`（兼容云库英文列 / 腾讯文档中文「归属班级」列 / 文本数组）。
  两个演示 mock 用 `flowCls()` 补空 `cls` 保持契约同形（演示数据无班级，标签自动隐藏）。
- **前端**：领用审批、我的申请 / 我的借还、出入库流水、操作日志、报修、巡检共 6 处列表
  用 `<view wx:if="{{item.cls}}">` 展示归属班级；`cls` 为空（公共资源）时不显示，避免空白标签。
- 未新增任何页面、未新增班级选择器，符合「班级不需要新页面，流水显示班级即可」。
- ⚠️ 线上 `docsProxy` 仍是旧版时，新产生的流水不会写 `cls`，班级标签会显示为空；
  部署新版云函数后才会自动盖章并显示。

## 十、版本迭代的数据向下兼容

### 10.1 结论（2026-11-16 核查）

**字段级兼容成立**：`cls` / `managedClasses` 属「只增列、不删列、不改枚举」；
旧数据缺列时一律走缺省（空 cls = 公共资源，空带班 = 不额外授权），
不丢数据、不抛异常；旧前端忽略未知字段，6 处班级展示均有 `wx:if` 判空。
`node tools/audit_compat.js` 当前 35 条断言全绿。

**语义级兼容不自动成立**：行级过滤在**读取时实时裁决**，因此新版云函数一旦部署，
新规则立刻作用于全部历史行，而不是只对新增数据生效。缺 `cls` 的历史流水会变成
「公共资源」（宽松，数据不丢），但教师若漏配带班则会「失明」。
项目目前**没有 `schemaVersion` 字段、没有自动迁移/回填框架**，
所以不能承诺「任意版本迭代天然兼容」，必须按 10.3 逐次确认。

### 10.2 兼容性契约（今后新增字段必须遵守）

| # | 规则 | 现有实现 |
|---|---|---|
| 1 | 只增列 / 不删列 / 不改枚举含义 | `COL` 双映射 + `TR` 中英状态双向翻译 |
| 2 | 缺字段必须有缺省，且缺省语义安全 | `readCls()→''`、`parseClasses()→[]` |
| 3 | 读归一化同时认新旧写法 | `readCls` 认英文 `cls` / 中文「归属班级」/ 文本数组 |
| 4 | 前端对新增展示字段一律判空 | 6 处 `wx:if="{{item.cls}}"` |
| 5 | 写操作禁止降级到备用后端 | `backend-switch.WRITE_ACTIONS` |
| 6 | 每个破坏性变更配一键止损开关 | `DATA_SCOPE=off`（不改数据，秒级回退） |
| 7 | **局部更新，禁止整行覆盖** | 云库 `doc().update({data: values})`；腾讯文档 `updateRecords` 按列写 |

> 第 7 条是「旧云函数写新数据不抹掉 `cls`」的关键。若改成整行覆盖，
> 老实例更新一条带 `cls` 的记录会把它清空，该记录随即退化为公共资源。

### 10.3 发版前数据兼容闸门

```bash
node tools/audit_compat.js                     # 35 条断言 + 风险清单（离线，不改数据）
python tools/audit_term_mapping.py --check     # 原始工作量表 vs 学期主数据
node tools/audit_online_scope.js --term <学期> # 线上账号归属 + 云函数版本 + 隔离模拟
node tools/smoke.js && node tools/test-rbac.js && node tools/test-data-scope.js \
  && node tools/test-robot-channel.js   # 30 条：机器通道 fail-closed + 身份自查 + 超级钥匙红线
```

部署顺序：① 备份（全库快照 + `users` 快照）→ ② 前端包与 `docsProxy` **成对上传** →
③ `diag` 核对 `backend/dataBackend` 与版本 → ④ 抽查一位教师「只看本班」→
⑤ 异常时 `DATA_SCOPE=off` 止损，再排查，不要直接回滚数据库。

### 10.4 已知缺口（本轮只核查，未改生产代码）

完整 7 条见 `tools/audit_compat.js` 输出，其中影响最大三条：

- **R1 历史流水无 `cls`**：部署后全部视为公共资源，所有教师可见；数据不丢，但历史记录
  无法按班隔离。当前线上业务数据刚清库、量极小，**此刻部署是代价最小的窗口**；
  若以后积累了大量无 `cls` 流水，须先写回填脚本（按 `user` 反查 `users.cls`）再部署。
- **R2 未配 `managedClasses` 的 teacher**：只能看到公共资源，本班申请全部不可见。
  新增教师账号后必须跑 `audit_online_scope.js` 校验带班完整。
- **R4 云库 `getRecords` 的 `recordIDs` 早退分支未做行级过滤**，与 `tencentdocs` 的
  `applyScope` 行为不一致，精确取行时会绕过隔离；属权限逻辑变更，须用户确认后修复。

另有 R3（腾讯文档备用表缺列静默退化）、R5（单一云环境、开发/体验/正式版共享同库、
无版本化灰度）、R6（云函数更新期新旧实例并存产生混合 `cls` 数据）、
R7（切回腾讯文档会读到另一套数据，属双库分裂而非格式不兼容）。
