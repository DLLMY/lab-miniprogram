- [ ] 2. 配置云函数**环境变量**（控制台 → 云函数 → 配置 → 环境变量）：
  - [ ] `DATA_BACKEND=cloud`（走云数据库；若先用腾讯文档则填 `tencent` 并配腾讯文档凭证）
  - [ ] `ROBOT_KEY=<管理员自定义高强度串>`（仅你知晓，绝不给教师）

- [ ] 3. **打通 WorkBuddy 与本机连接器的桥接**（二选一，推荐方案 B）：
  - **方案 B（推荐·SDK 直连，无需公网、无需升级付费）**：`cloud1` 首次创建时已**自动绑定**一个腾讯云账号（控制台没有「绑定」按钮是正常的）。用**小程序管理员**微信以「微信公众平台」方式扫码登录 [console.cloud.tencent.com](https://console.cloud.tencent.com) → **访问管理 → API 密钥管理** 创建 `SecretId`/`SecretKey`；环境 ID 在微信开发者工具「云开发 → 设置 → 环境设置」复制（形如 `cloud1-xxxxxxxx`）。本机 `mcp.json` 填 `TCB_SECRET_ID`/`TCB_SECRET_KEY`/`TCB_ENV` 三项即可，**无需在控制台建任何 HTTP 路由**。
  - **方案 A（HTTP 触发）**：在云开发控制台 **「HTTP 访问服务」**（不在函数详情的"触发器"里，触发器是给数据库/定时任务用的）为 `docsProxy` **添加路由**，路径 `/docsProxy`，**鉴权选「不鉴权」**；记录生成的公网地址（形如 `https://xxx.apigw.tencentcs.com/release/...` 或 `https://<env>.ap-shanghai.app.tcloudbase.com/docsProxy`），后续填进 `mcp.json` 的 `DOCS_PROXY_HTTP_URL`（带完整 `/docsProxy` 路径）。⚠️ 体验版环境需先升级付费才看得到入口。

> ⚠️ 切勿把 `env.local.js` 里的明文 token 直接贴到控制台；控制台环境变量与本地 `env.local.js` 二选一即可，本项目用**控制台环境变量**为准。

### 第四轮收口：新建功能的隐藏缺陷（与上一节同批提交）

上一节 5 项功能是**新写的代码**，首次真机使用前必须修掉以下 8 项（均已在本地完成）：

- [ ] **二维码画布尺寸**：旧版 canvas 的绘制坐标系 = 画布 CSS 像素尺寸。此前画布写的是 `700rpx`（真机约 350px）
  而绘制逻辑用 700×990 逻辑坐标 → 标签右半边画到画布外被裁掉，导出的图放大后还模糊。
  已改为 `700px × 990px`（与坐标 1:1），并把离屏容器从 `fixed` 改为 `absolute`。
- [ ] **二维码页禁止用演示数据打印**：列表读取改走 `callFull(..., { noFallback: true })`，
  云端失败即报错；云函数 `USE_MOCK=true` 时页面显示醒目黄条并**禁用生成按钮**——
  否则会把 `M001` 这类演示物品的码打印出来贴到真机上，扫出来查无此物。
- [ ] **全站演示模式警示**：首页此前在 `index.js` 算了 `isDemo` 却**从未在模板渲染**，
  云函数配错时全站静默使用假数据、老师把真实领用记进演示台账。现已在首页顶部加黄条警示，
  且判定改到**取数之后**（原先读到的是上一次会话的旧值）。
- [ ] **撤销回滚不再依赖「来源类型」列**：原先查找出库流水要求 `src === '领用出库'`，
  而腾讯文档表若未手工加该列，`buildValues` 会跳过 → src 恒空 → **永远匹配不到，库存不回补却把单子标成已撤销**。
  现改为以 `note`（审批写入，必有）为锚点，`src` 仅作增强条件。
- [ ] **撤销回滚失败要如实报**：找不到账务影响时不再写「已撤销（无需回滚）」，
  改为三态 `rolledBack / none / missing`，`missing` 时前端弹窗提示「库存可能未回补，请人工核对」。
- [ ] **相册权限只提示一次**：`saveAll` 逐张保存时，权限被拒会弹 N 次弹窗，改为只弹一次。
- [ ] **二维码页切号后重算权限**：`onShow` 重新校验身份并重取数据，不残留上一位教师的清单与勾选。
- [ ] **mock 用户列表按真实身份过滤**：演示模式原按前端传入的 `data.role`（默认 `super`）返回全部账号，
  与线上「教师只见本班学生」分叉；改为按 `data.actor` 判定，三处前端调用同步带上 actor。

### 第十五轮：工号 ↔ 微信绑定限制的核验、加固与回归固化

用户确认：「如果一个工号被 openid 绑定，其他账号应该是无法进行绑定，有这样一条限制就够了」。

#### 核验结论：这条限制本来就实现且有效，但有两个真缺陷

用真实链路（打桩 wx-server-sdk + 内存伪云库 + `prodDispatch`）实测 10 组场景，结论：

| 场景 | 实际行为 | 判定 |
|---|---|---|
| 未绑定工号首次绑定 | 成功，openid 写入该工号行 | ✅ |
| 同一微信重复绑同一工号 | 幂等放行（code 0） | ✅ |
| **另一微信绑已绑定的工号** | **409「该工号已绑定其他微信，无法重复绑定」，openid 未被覆盖** | ✅ **核心限制有效** |
| 同一微信绑另一工号 | 409「一个微信只能绑定一个工号」 | ✅ |
| 姓名与工号不匹配 | 400 | ✅ |
| 账号已停用 | 400 | ✅ |
| 管理员停用账号 | openid **保留**（停用≠解绑） | ✅ |
| 管理员改工号 | openid **随行保留**，新工号同样受保护 | ✅ |
| **物理删除已绑定账号 → 同工号重建** | **重建后无绑定保护，任意微信可抢绑** | ❌ **限制被绕过** |
| 409 提示「请联系管理员清空绑定」 | **管理员根本没有清空绑定的入口** | ❌ **换绑是死路** |

#### 修掉的两处

- [ ] **删除已绑定微信的账号 → 409 拒绝**（两套适配器 + 两套 mock）：
      物理删除会让 openid 随行消失 → 同工号重建后处于「未绑定」状态，
      「一个工号被绑定后他人不可再绑」这条保护随之失效 → 任何人都能抢绑该工号（实测复现）。
      现在提示「请改用『停用』（保留档案与绑定），或先『解绑』再删除」。
      **未绑定微信的账号仍可正常删除**（错录脏账号要能清）。
- [ ] **新增 `adminUnbindUser`（解除微信绑定）**：清空该工号的 openid，使其可重新绑定。
      这是「工号↔openid 一对一」能被纠错的**唯一正规出路**（本人换微信号、绑定录错时使用）。
      闸门 `gStaff`，细分与编辑/删除同口径：super 任意；admin 教师/学生；teacher 仅**本班**学生
      （层级裁决 + `userScopeErr` 数据域裁决）。解绑写日志留痕（谁、何时、解了谁）。

#### 前端

- [ ] 用户管理页：已绑微信的账号行新增 **「解绑」** 操作（二次确认，说明"解绑后该工号可被任何人重新绑定"）。
- [ ] 删除已绑定账号时不再直接进删除流程，改为引导：

### 第十八轮：跨实例并发安全（CAS）+ 弱网重试（架构级加固）

用户指令：「按照建议继续优化」→ 落实上一轮建议的两件事：
① **跨云函数实例的并发安全**（进程内写锁挡不住多实例部署）；
② **前端弱网超时后的重试**（请求其实已执行，用户看到失败会再点一次）。

#### ① 跨实例并发：把「期望值」下沉到数据库（CAS）

**根因**：库存与工具状态的写入是「读 → 算 → 写」三步，`withWriteLock` 只是**进程内**的 Promise 串行链 ——
CloudBase 多实例部署时，两个实例互相看不见对方的锁，各自读到同一个旧值、后写的覆盖先写的
→ 入库少加 / 审批双扣 / 同一件工具被借两次。

**改法**（`clouddb.js`）：新增三个函数，把期望值写进 `where` 条件，由数据库保证原子性：

| 函数 | 作用 |
|---|---|
| `casUpdate(sheet, recordId, condition, fields)` | 条件更新：只有记录仍满足 condition 才写入；返回 `{ok, updated}` |
| `atomicAdjustStock(recordId, delta)` | 原子增减库存：条件是读到的期望值；不匹配则重读重试（最多 4 次）；算出负数=库存不足 |
| `atomicSwitchToolStatus(recordId, from, to, extra)` | 原子切换工具状态：状态仍是「在库」才借出 → 同一件工具不会被借两次 |

**改造的 9 个写入点**（两套适配器同步）：
`io` / `batchIo` / `approve`（耗材分支扣减 + 工具分支借出）/ `borrow` / `returnTool`（归还回库）/
`revokeApprove`（撤销回库）/ `stocktake`（写实盘）/ `reverseIO`（冲销回滚）。

**平台差异（必须知道）**：
- **云库**：真 CAS（`where` 条件更新）。
- **腾讯文档**：表格 API 只能整行读改写，**没有条件更新** → 同名同签名的降级实现（条件校验 + 写入），
  单实例内靠写锁、跨实例仍有极小漏网概率。生产主后端是云库，腾讯文档只是回退兜底。
  两套适配器的**业务代码保持完全同构**，差异只在 CAS 函数内部。

**顺带修正的语义不一致**：CAS 失败（工具被别人借走）原本抛错 → 变 500 服务器故障；
已改为与串行路径同口径的 **400 业务错误**「该工具不在库（已被他人借走）」。

#### ② 弱网重试

- **幂等窗口 5 秒 → 30 秒**：弱网/超时后请求其实已到达服务器并执行，用户看不到结果会再点一次；
  5 秒太短（人反应不过来），30 秒能覆盖「看到失败提示 → 反应过来 → 再点」的典型间隔。
  命中时挂 `idem/deduped` 标记 + 明确文案，前端提示「检测到重复提交（相同内容），本次未重复执行」。
- **失败文案不再诱导盲目重试**：503/超时的提示改为
  「云函数调用失败…若刚才的提交已到达服务器，可能已经生效 —— 请先刷新页面核对，确认没生效再重试」。
- **补齐漏网的幂等提示**：io 页的「登记出入库」与「扫码批量登记」两条高频路径此前没接 `idemWarn` → 已补。

  - **⑨ 跨实例并发**：用「清 require 缓存后重新 require 适配器」造出第二个云函数实例
