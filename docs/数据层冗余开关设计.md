# 数据层冗余开关设计（开发期热切换 · 防崩溃）

> 适用：`lab-miniprogram` 云函数 `cloudfunctions/docsProxy`
> 关联方案：《数据层迁移方案-腾讯文档到云数据库.md》（方案 C）
> 状态：**已落地**（新增 `backend-switch.js` + 改造 `index.js` 分发层；回归 13/13 通过）

---

## 1. 要解决的问题

开发/上线期间，数据底座可能随时"跛脚"：

- 腾讯文档 `access_token` 每 30 天必断（当前 2026-11-21 到期）→ 生产路径大面积 500；
- 切到云数据库（方案 C）后，若 8 个集合没建好 / `clouddb.js` 还没写 → `require` 直接抛错；
- 只想临时验证某后端，却不得不改代码、重新部署。

目标：**一个环境变量开关就能在「云文档 / 云函数云库 / 演示」之间切换；任一后端崩了，自动倒下一个，绝不把整次请求拖崩。**

---

## 2. 架构：三层后端 + 一层冗余分发

```
小程序前端 pages/**
   │  wx.cloud.callFunction: docsProxy
   ▼
cloudfunctions/docsProxy/index.js   ← 调度层 + 权限闸（不变）
   │
   │  ┌─────────── 冗余分发（本次新增）───────────┐
   │  │ 按回退链依次尝试，抛异常即切下一个          │
   │  └────────────────────────────────────────────┘
   ▼
backend-switch.js 解析 DATA_BACKEND / USE_MOCK / FALLBACK
   → 构建有序回退链，选出本次请求可用的后端
   ▼
┌─────────────┬─────────────┬──────────────┐
│ tencentdocs │  clouddb.js │ mockHandler  │   ← 三个数据实现（契约一致）
│ （云文档）   │ （云函数云库）│ （内存演示）   │
└─────────────┴─────────────┴──────────────┘
```

关键设计点：

- **后端选择抽成纯模块 `backend-switch.js`**（无任何 `require('wx-server-sdk')` 等外部依赖），便于单测与热切换；
- `index.js` 的分发层只认 `CHAIN`（回退链），**业务函数、权限闸、前端契约完全不动**；
- `prodHandler` 改为 **按请求接收 `tdModule` 参数**（不再依赖模块级可变 `td`），保证并发安全——两个并发请求选不同后端时不会串台。

---

## 3. 三个开关（均为云函数环境变量，免改代码）

| 变量 | 取值 | 含义 |
|---|---|---|
| `USE_MOCK` | `'true'` | 强制走内存演示（mock），不回退 |
| | `'false'` | 强制走真实后端，且**关闭**自动回退（想看真实报错时用） |
| | 不设 | 自动模式：按凭证/回退链自适应 |
| `DATA_BACKEND` | `'tencent'`（默认） | 真实后端 = 腾讯文档（云文档） |
| | `'cloud'` | 真实后端 = 微信云数据库（云函数内 `clouddb.js`） |
| `FALLBACK` | `'on'`（默认）/ 不设 | 主后端异常时**自动切下一个**后端 |
| | `'off'` | 关闭自动回退（调试用，直接暴露真实错误） |

> `USE_MOCK` 与 `DATA_BACKEND` 的关系：`USE_MOCK='true'` 优先级最高（直接 mock）；否则真实后端由 `DATA_BACKEND` 决定。

---

## 4. 自动回退链（防崩溃核心）

| 主后端 | 回退链 | 说明 |
|---|---|---|
| `tencent` | `tencent → mock` | token 过期/网络抖动 → 自动落到演示数据，开发不中断 |
| `cloud` | `cloud → tencent → mock` | 云库未建集合 → 退腾讯文档；文档也挂 → 退演示 |
| `mock` | `mock`（无回退） | 演示唯一来源 |

回退触发条件：**后端处理函数抛异常**（如 `td.warmFieldMaps()` 因 token 失效失败、`require('./clouddb.js')` 不存在、云库查询超时）。

兜底保证：即使所有后端都失败，也只返回**结构化 500**（`{code:500, msg, backend:'none', fallback:true}`），**不会让云函数进程崩溃**。

### 优雅降级的两个"不崩"细节
1. `loadBackend()` 捕获 `require` 异常 → `clouddb.js` 还没写时选 `cloud` 不会炸，只是静默跳过、落到 tencent/mock；
2. 自动模式下若选 `tencent` 但**凭证缺失**，主后端直接降级为 `mock`，避免无意义地狂打失效 token。

## 5. 可观测性（一眼看清当前跑的是谁）

每次响应在保留原 `src` 契约（`'mock'` / `'cloud'`，前端 `utils/api.js` 据此显示"真实腾讯文档/本地演示"）的同时，额外附带：

```jsonc
{
  "src": "cloud",        // 前端原契约，不变
  "backend": "tencent",  // 本次实际服务后端：tencent | cloud | mock
  "fallback": true       // 由非主后端兜底提供（true=发生了回退）
}
```

「我的 → 云端自检」(`action:'diag'`) 现在还会回显：

```jsonc
{
  "backend": "tencent",
  "chain": ["tencent", "mock"],   // 当前生效的回退链
  "autoFallback": true,
  "dataBackend": "tencent",
  "hasCredential": true
}
```

开发期打开「我的」页一点自检，就能确认切换有没有生效、是不是在靠回退跑。

## 6. 开发期怎么用（典型场景）

| 想做的事 | 操作（云函数环境变量） |
|---|---|
| 照常连腾讯文档 | `USE_MOCK` 不设 / `DATA_BACKEND=tencent` |
| 临时纯演示，不碰任何真实数据 | `USE_MOCK=true` |
| 切到云数据库验证（方案 C） | `DATA_BACKEND=cloud`（需先写好 `clouddb.js` + 建 8 集合） |
| 想看真实报错、不要被回退掩盖 | `FALLBACK=off` |
| 腾讯文档 token 半夜过期 | 什么都不用做：自动回退 mock，开发/演示不中断；修好 token 后自动恢复 |

> 所有切换**只改环境变量 + 重新部署云函数**，无需改代码、无需重新发包。

## 7. 与迁移方案 C 的衔接

- `clouddb.js` 只需导出与 `tencentdocs.js` **完全一致**的 `module.exports`（含 `runtimeInfo` 改写），`backend-switch.js` 即可无缝把它接入回退链；
- 上线节奏：`DATA_BACKEND` 默认 `tencent` → 写好 `clouddb.js` 后切 `cloud` → 稳定后清掉 4 个腾讯文档 token 变量（此时 `tencent` 因无凭证自动降级，等于"软下线"），旧 `tencentdocs.js` 保留可随时回滚。
