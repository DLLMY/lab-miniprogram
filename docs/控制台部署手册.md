# 实训室管理系统 · 控制台侧手动部署详细步骤

> 适用对象：管理员（你自己）。本文覆盖**控制台（微信开发者工具「云开发」+ CloudBase HTTP 触发）**必须手动点完的所有步骤。
> 代码已就绪、已提交。此前已做的关键修复：云函数 `docsProxy` 已兼容 **HTTP 触发**返回格式（`{statusCode,headers,body}`），因此从 WorkBuddy 经 HTTP 调用可正确回传 JSON 信封。
> 读完对照 `部署检查清单.md` 逐项勾选即可。

---

## 0. 前置准备（一次性）

| 项目 | 说明 |
| --- | --- |
| 微信开发者工具 | 已导入本项目（`miniprogramRoot: ./`，AppID `wxf61364cb15c58653`） |
| 云开发环境 | 已在开发者工具开通「云开发」，**记下环境 ID**（形如 `lab-management-xxx`） |
| ROBOT_KEY | 管理员自定义**高强度随机串**（≥32 位，含大小写+数字+符号）。**只你自己知道，绝不给教师** |
| 本机 Node | ≥ 16（仅用于本机 WorkBuddy MCP，不进云端） |
| 数据底座决策 | 二选一：① `DATA_BACKEND=cloud`（云数据库，推荐，本文主线）；② `tencent`（腾讯文档，需另外填 4 项腾讯文档凭证） |

> 若选 `tencent` 后端，还需准备 `TENCENT_DOCS_FILE_ID / CLIENT_ID / ACCESS_TOKEN / OPEN_ID` 四项，并在步骤 2 一起填进环境变量。本文以 `cloud` 为主线。

## 1. 上传并部署云函数 `docsProxy`

1. 在微信开发者工具左侧**资源管理器**找到 `cloudfunctions/docsProxy`。
2. **右键** → 选择 **「上传并部署：云端安装依赖」**（首次选这个，让云端 `npm install wx-server-sdk`）。
3. 等待进度条完成，底部出现「上传成功」。**控制台「日志」里显示「共 0 条」是正常的**（还没有调用）。
4. 若已传过旧版，直接右键 → **「上传并部署」** 覆盖即可（含本次个人密钥 / L1 确认门 / `alerts` / 月末趋势修复）。

> ⚠️ 上传后**环境变量不会自动带过来**，必须走步骤 2 单独在控制台配。

---

## 2. 配置云函数环境变量（关键）

1. 开发者工具顶部点 **「云开发」** 打开控制台。
2. 左侧 **云函数** → 选 `docsProxy` → **配置** 标签 → **环境变量** → **编辑**。
3. 按下面表格逐条新增（键值对，**不要带引号**）：

| 变量名 | 取值 | 说明 |
| --- | --- | --- |
| `DATA_BACKEND` | `cloud` | 走云数据库（推荐）；`tencent` 则走腾讯文档 |
| `ROBOT_KEY` | `<你第 0 步生成的高强度串>` | WorkBuddy 机器通道总密钥（管理员应急 super 通道） |
| `ROBOT_ACTOR_ID` | `T001` | 应急超级通道身份（与 users 表管理员工号一致） |
| `USE_MOCK` | （**留空不填**） | 留空=自动模式（有凭证走真数据、无凭证降级 mock） |
| `FALLBACK` | （**留空不填**） | 留空=自动回退开启（某后端报错自动切下一个） |

4. 点 **保存**。
5. **为使环境变量生效，建议再右键 `docsProxy` → 「上传并部署」一次**（环境变量对新容器实例生效，重传最稳）。

> ❌ 不要把本机 `env.local.js` 的明文 token 贴到控制台。控制台环境变量与本地 `env.local.js` **二选一**，本项目以**控制台为准**。
> ✅ 控制台环境变量不会进公开 Git 仓库（已 gitignore 排除 `project.private.config.json` 与 `env.local.js`）。

## 3. 调大超时与内存（必做，否则审批/批量超时）

仍在 `docsProxy` → **配置** 标签：

- **超时时间**：默认 3s，改为 **60s**（审批、批量出入库、迁移可能超 3s）。
- **内存**：默认 256MB 即可；若迁数据卡顿可提到 512MB。
- 保存。

> 这条直接对应「审批延迟太高/超时」类线上问题。务必改。

---

## 4. 创建 HTTP 触发（WorkBuddy 桥接，关键）

WorkBuddy 在本机通过 HTTP 调云函数，因此必须开一个对外 HTTP 触发：

1. `docsProxy` → **触发管理** 标签 → **创建触发**。
2. 触发类型选 **「HTTP 触发」**。
3. 触发路径填 **`/docsProxy`**（函数名，便于识别）。
4. 方法勾选 **POST**（也可全勾，无妨）。
5. 点 **创建**。

创建成功后会给出一个**公网地址**，形如：

- `https://<env>.ap-shanghai.app.tcloudbase.com/docsProxy`，或
- `https://<apigw-id>.apigw.tencentcs.com/release/docsProxy`

**复制这个完整 URL 保存好**——后面填进本机 `mcp.json` 的 `DOCS_PROXY_HTTP_URL`。

> 这是 WorkBuddy 与小程序共享的同一套后端。教师与你用**同一个 URL**，只是各自填自己的密钥。

## 5. 云数据库集合（`DATA_BACKEND=cloud` 时必须）

1. 云开发控制台左侧 **数据库**。
2. 点 **「+ 新建集合」**，依次创建以下 **11 个**集合：

   ```
   users  materials  tools  requisitions  borrow
   stock_io  access  logs  labs  repairs  inspections
   ```

3. 每个集合建好后，点进集合 → **权限设置** → 选 **「仅管理端可读写」**（云函数以 admin 身份访问不受此限，设最严即可，防前端直连越权）。
4. 若从腾讯文档迁移历史数据：以管理员身份在小程序内调 `migrate`，源数据保留不删、可回滚（见 `迁移方案.md`）。全新部署可跳过。

## 6. 验证 HTTP 触发是否真正连通

在本机终端（PowerShell / bash 均可）发一条诊断请求，**把 URL 和 ROBOT_KEY 换成你自己的**：

```bash
curl -X POST "https://<你的HTTP触发URL>" \
  -H "Content-Type: application/json" \
  -d '{"action":"diag","robotKey":"<你的ROBOT_KEY>"}'
```

**期望返回**（外层是 HTTP 包裹，内层是业务信封）：

```json
{
  "statusCode": 200,
  "headers": { "Content-Type": "application/json" },
  "body": "{\"code\":0,\"src\":\"cloud\",\"backend\":\"cloud\",\"data\":{ ... }} "
}
```

- `body` 里 `code:0` 且 `backend:"cloud"` → 已接真实云数据库 ✅
- 若 `body` 是 `code:500` 或空 → 回控制台看 `docsProxy` 日志，多半是环境变量没生效或集合没建。
- 若外层连不上（curl 超时/443 拒绝）→ 检查第 4 步触发路径、URL 是否完整带 `/docsProxy`。

> 上述 `diag` 用管理员 `ROBOT_KEY` 能回显后端指纹；教师用各自个人密钥只能拿到自己权限内的数据。

## 7. 上传小程序前端

1. 微信开发者工具右上角 **「上传」**（图标像向上箭头）。
2. 填 **版本号**（如 `1.0.0`）和 **备注**（如「含个人机器人密钥卡片 + L1 确认门」）→ 确定。
3. 登录 [微信公众平台](https://mp.weixin.qq.com) → **版本管理**：
   - 个人主体只能走 **体验版 + 体验成员**（≤15 人，免审核，最快）；
   - 需要对外搜索/分享码则须转**学校主体**认证后提交审核。
4. 把需要的教师加入 **体验成员**（公众平台 → 成员管理 → 体验成员）。

## 8. 教师自连接（每位老师各自完成）

教师操作（无需管理员介入）：

1. 打开实训室小程序 → **「我的」** 页。
2. 找到 **「个人机器人密钥」** 卡片 → 点 **生成**。
3. 明文密钥**只显示一次**，复制保存到自己本机（如记事本/密码管理器）。
4. 按 `docs/教师自连接操作卡.md` 在本机配好 WorkBuddy 的 `mcp.json`（URL 全校共用，密钥填自己的）。
5. 信任启用后测试：`查询我名下待处理报修`、`查 A 柜物料`。

> 教师密钥可在「我的」页随时**吊销**，吊销即失效，无需管理员干预。

## 9. 本机 WorkBuddy MCP 配置（管理员 & 教师通用）

管理员（`mcp.json` 示例，填**自己的** `ROBOT_KEY`）：

```json
{
  "mcpServers": {
    "lab-docs-proxy": {
      "command": "node",
      "args": ["<绝对路径>/lab-miniprogram/mcp/docs-proxy-server.js"],
      "env": {
        "DOCS_PROXY_HTTP_URL": "https://<步骤4的HTTP触发URL>",
        "DOCS_PROXY_ROBOT_KEY": "<管理员ROBOT_KEY 或 教师个人密钥>"
      }
    }
  }
}
```

- 管理员填 `ROBOT_KEY`（super 通道）；教师填**自己的个人密钥**。
- 在 WorkBuddy **连接器列表信任启用** `lab-docs-proxy`，发一句「查低库存物料」验证只读可用。

1. WorkBuddy → 自动化 → 找到 **「实训室每日预警推送」**，确认状态为**启用**（每日 08:20）。

## 11. 常见问题排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| HTTP 触发返回空 / 不是 JSON | 环境变量未生效 | 重传 `docsProxy`（步骤 1+2 再走一遍） |
| `code:500` / `所有数据后端均不可用` | 集合未建或权限不对 | 回步骤 5 建 11 个集合、权限「仅管理端可读写」 |
| `backend:"mock"` 而非 `cloud` | `DATA_BACKEND` 没设对或凭证缺失 | 确认环境变量 `DATA_BACKEND=cloud` 已保存并重新部署 |
| 写操作永远返回 `[确认码 Cxxx]` 不执行 | 这是 **L1 确认门** 正常工作 | 再发一次 `lab_confirm` 带确认码即可真正写入 |
| 审批/批量卡住超时 | 超时时间仍是 3s | 步骤 3 改 60s |
| 教师查不到数据 | 教师用个人密钥，权限=本人身份 | 正常；教师只能看本人权限内数据，管理员用 `ROBOT_KEY` 可看全部 |
| 控制台「保存」按钮转圈 | 控制台偶发卡 | 改用 `env.local.js` 兜底（见 `上线操作手册.md` 2.2），或刷新重登 |

## 12. 安全红线（务必遵守）

- ❌ 绝不把管理员 `ROBOT_KEY` 发给任何教师（教师用各自个人密钥）。
- ❌ 绝不把 `env.local.js` 明文提交到公开仓库（已 gitignore）。
- ❌ 教师写操作必须经 L1 确认门，连接器不绕过。
- ✅ 密钥可随时在「我的」页吊销，吊销即失效。
- ✅ 机器通道默认 **fail-closed**：`ROBOT_KEY` 未配置且无可解析个人密钥时，外部调用只能走公开只读接口。
