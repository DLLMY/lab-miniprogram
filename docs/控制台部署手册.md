> 适用对象：管理员（你自己）。本文覆盖**控制台（微信开发者工具「云开发」+ CloudBase HTTP 触发）**必须手动点完的所有步骤。
> 代码已就绪、已提交。此前已做的关键修复：云函数 `docsProxy` 已兼容 **HTTP 触发**返回格式（`{statusCode,headers,body}`），因此从 WorkBuddy 经 HTTP 调用可正确回传 JSON 信封。

## 1. 上传并部署云函数 `docsProxy`

1. 在微信开发者工具左侧**资源管理器**找到 `cloudfunctions/docsProxy`。
2. **右键** → 选择 **「上传并部署：云端安装依赖」**（首次选这个，让云端 `npm install wx-server-sdk`）。
3. 等待进度条完成，底部出现「上传成功」。**控制台「日志」里显示「共 0 条」是正常的**（还没有调用）。
4. 若已传过旧版，直接右键 → **「上传并部署」** 覆盖即可（含本次个人密钥 / L1 确认门 / `alerts` / 月末趋势修复）。

> ⚠️ 上传后**环境变量不会自动带过来**，必须走步骤 2 单独在控制台配。

## 2. 配置云函数环境变量（关键）

1. 开发者工具顶部点 **「云开发」** 打开控制台。
2. 左侧 **云函数** → 选 `docsProxy` → **配置** 标签 → **环境变量** → **编辑**。
3. 按下面表格逐条新增（键值对，**不要带引号**）：

| 变量名 | 取值 | 说明 |
| --- | --- | --- |
| `DATA_BACKEND` | `cloud` | 走云数据库（推荐）；`tencent` 则走腾讯文档 |
| `ROBOT_KEY` | `<你第 0 步生成的高强度串>` | WorkBuddy 机器通道总密钥（管理员应急 super 通道） |
| `ROBOT_ACTOR_ID` | `T001` | 应急超级通道身份（与 users 表管理员工号一致） |
| `USE_MOCK` | （**留空不填**） | 留空=自动模式（有凭证走真数据、无凭证降级 mock） |
| `FALLBACK` | （**留空不填**） | 留空=自动回退开启（某后端报错自动切下一个） |

4. 点 **保存**。
5. **为使环境变量生效，建议再右键 `docsProxy` → 「上传并部署」一次**（环境变量对新容器实例生效，重传最稳）。

> ❌ 不要把本机 `env.local.js` 的明文 token 贴到控制台。控制台环境变量与本地 `env.local.js` **二选一**，本项目以**控制台为准**。
> ✅ 控制台环境变量不会进公开 Git 仓库（已 gitignore 排除 `project.private.config.json` 与 `env.local.js`）。

## 4. 让 WorkBuddy 连上云函数（两种桥接方式）

WorkBuddy 在本机调 `docsProxy` 云函数，有两条路。**推荐方案 B（SDK 直连）**：不出公网、不经 HTTP 访问服务，彻底绕开体验版的"保护性限制"与付费升级。

### 方案 B（推荐）：CloudBase Node SDK 直连，无需公网 HTTP 入口

连接器用 `@cloudbase/node-sdk` 的 `callFunction` 直接调云函数，因此**无需在控制台建任何 HTTP 路由、无需升级付费环境**。

1. **拿腾讯云 API 密钥**：首次在微信开发者工具内创建 `cloud1` 时，系统已**自动**为该小程序创建并绑定了一个腾讯云账号（无需、也找不到手动「绑定」按钮，这是正常现象）。你只需去登录那个腾讯云账号拿密钥即可：
   - 浏览器打开 [console.cloud.tencent.com](https://console.cloud.tencent.com) → 登录方式选 **「微信公众平台」扫码**（用**小程序管理员**的微信扫）→ 进入后左侧 **访问管理 → API 密钥管理 → 新建密钥**，记下 `SecretId` / `SecretKey`。
   - 若登录后看不到 `cloud1` 环境或无法建密钥：说明你扫的账号不是绑定 `cloud1` 的那个，换小程序管理员微信、用「微信公众平台」方式扫码即可。
2. **拿环境 ID**：在 **微信开发者工具 → 云开发 → 设置 → 环境设置** 复制环境 ID（形如 `cloud1-xxxxxxxx`）。
3. 本机 `mcp.json` 填 `TCB_SECRET_ID` / `TCB_SECRET_KEY` / `TCB_ENV` + 个人密钥（见第 9 节「方案 B」模板）。
4. 重启 WorkBuddy 连接器即可。

> ⚠️ 若 `callFunction` 报「环境不存在 / 无权限」：说明你登录腾讯云用的账号与 `cloud1` 绑定的不是同一个。回到步骤 1，用**小程序管理员**微信以「微信公众平台」方式扫码登录那个自动创建的腾讯云账号。

#### 联调验证（可选但推荐）：`tools/diag-sdk.js`

无需启动 WorkBuddy，先用脚本验证「账号选对 / 密钥通 / 环境可达」：

```bash
# 方式一：环境变量
TCB_SECRET_ID=xxx TCB_SECRET_KEY=yyy TCB_ENV=cloud1-xxxxxxxx DOCS_PROXY_ROBOT_KEY=zzz node tools/diag-sdk.js
# 方式二：本地密钥文件（已被 .gitignore 忽略，不入库）
#   在 mcp/diag.local 写 {secretId,secretKey,env,robotKey}，再运行：
node tools/diag-sdk.js
```

- `✓ 连通成功！code=0` → 一切正常；
- `环境不存在/无权限` → 腾讯云账号选错，换另一个重做密钥；
- `SecretId/SecretKey 不对` → 密钥失效，重建一对。

> ✅ **本项目已实测**（2026-10-31）：本脚本返回 `code=0, backend=cloud, dbReady=true, materialCount=5`，样本为真实云库数据，证实方案 B 全链路打通，无需公网 HTTP、无需升级付费环境。
>
> 管理员微信若对应**多个腾讯云账号**（管了多个小程序）：扫码登录后会出现账号选择，选 **拥有 `cloud1` 的那个**（即当前 lab 小程序对应的自动创建账号），其余账号里没有 `cloud1`。

### 方案 A（备选）：CloudBase HTTP 访问服务（需升级付费环境）

> ⚠️ **体验版限制**：微信云开发体验版（`cloud1`）对 HTTP 访问服务有保护性限制，内置与独立 CloudBase 控制台都看不到入口。必须先**升级为付费环境**才能建路由。不想升级就走方案 B。

**步骤 0（必做）：升级为付费环境**

1. 微信开发者工具 → 云开发控制台 → 概览，环境名下方横幅「调整计费模式」（或在 设置 → 环境设置）。
2. 选 **付费环境（建议按量付费）** → 提交订单（基础套餐约 19.9 元/月，环境 ID 与数据不变）。
3. 支付后关闭再重开控制台，HTTP 访问服务入口才显现。

**步骤 1：建路由**

- 左侧找 **「HTTP 访问服务」**（或「访问管理」「环境管理 → HTTP 访问服务」，升级后显示）。
- 添加路由：路径 `/docsProxy`，关联 `docsProxy`（POST）。
- **⚠️ 鉴权选「不鉴权 / 免登录」**——函数内部用 `robotKey` 自鉴权；选"需微信登录"会被外部 POST 拦成 403。
- 复制公网地址（形如 `https://<serviceId>.service.tcloudbase.com/docsProxy`），填进 `mcp.json` 的 `DOCS_PROXY_HTTP_URL`。

**备选：CLI 建路由**（升级后同样可用）

```bash
npm install -g @cloudbase/cli
cloudbase login
cloudbase service create -p /docsProxy -f docsProxy -e <你的环境ID>
```

> 若升级付费后仍无 HTTP 访问服务入口：改用方案 B（SDK 直连），或把环境切到独立 CloudBase 标准环境。

## 6. 验证 HTTP 触发是否真正连通

在本机终端（PowerShell / bash 均可）发一条诊断请求，**把 URL 和 ROBOT_KEY 换成你自己的**：

```bash
curl -X POST "https://<你的HTTP触发URL>" \
  -H "Content-Type: application/json" \
  -d '{"action":"diag","robotKey":"<你的ROBOT_KEY>"}'
```

**期望返回**（外层是 HTTP 包裹，内层是业务信封）：

```json
{
  "statusCode": 200,
  "headers": { "Content-Type": "application/json" },
  "body": "{\"code\":0,\"src\":\"cloud\",\"backend\":\"cloud\",\"data\":{ ... }} "
}
```

- `body` 里 `code:0` 且 `backend:"cloud"` → 已接真实云数据库 ✅
- 若 `body` 是 `code:500` 或空 → 回控制台看 `docsProxy` 日志，多半是环境变量没生效或集合没建。
- 若外层连不上（curl 超时/443 拒绝）→ 检查第 4 步触发路径、URL 是否完整带 `/docsProxy`。

> 上述 `diag` 用管理员 `ROBOT_KEY` 能回显后端指纹；教师用各自个人密钥只能拿到自己权限内的数据。

## 9. 本机 WorkBuddy MCP 配置（管理员 & 教师通用）

**方案 B（推荐·SDK 直连，无需公网地址）**：管理员或教师都用同一套 `TCB_*` 凭据 + 各自个人密钥。

```json
{
  "mcpServers": {
    "lab-docs-proxy": {
      "command": "node",
      "args": ["<绝对路径>/lab-miniprogram/mcp/docs-proxy-server.js"],
      "env": {
        "TCB_SECRET_ID": "你的腾讯云 SecretId",
        "TCB_SECRET_KEY": "你的腾讯云 SecretKey",
        "TCB_ENV": "cloud1-xxxxxxxx",
        "DOCS_PROXY_ROBOT_KEY": "<管理员ROBOT_KEY 或 教师个人密钥>"
      }
    }
  }
}
```

**方案 A（HTTP 触发，需先完成第 4 节升级+路由）**：

```json
{
  "mcpServers": {
    "lab-docs-proxy": {
      "command": "node",
      "args": ["<绝对路径>/lab-miniprogram/mcp/docs-proxy-server.js"],
      "env": {
        "DOCS_PROXY_HTTP_URL": "https://<步骤4的HTTP触发URL>",
        "DOCS_PROXY_ROBOT_KEY": "<管理员ROBOT_KEY 或 教师个人密钥>"
      }
    }
  }
}
```

- 三项 `TCB_*` 同时填，连接器自动走 SDK 直连；只填 `DOCS_PROXY_HTTP_URL` 则走 HTTP 触发。两者皆缺会友好报错。
- 管理员填 `ROBOT_KEY`（super 通道）；教师填**自己的个人密钥**。
- 在 WorkBuddy **连接器列表信任启用** `lab-docs-proxy`，发一句「查低库存物料」验证只读可用。

## 11. 常见问题排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| HTTP 触发返回空 / 不是 JSON | 环境变量未生效 | 重传 `docsProxy`（步骤 1+2 再走一遍） |
| `code:500` / `所有数据后端均不可用` | 集合未建或权限不对 | 回步骤 5 建 11 个集合、权限「仅管理端可读写」 |
| `backend:"mock"` 而非 `cloud` | `DATA_BACKEND` 没设对或凭证缺失 | 确认环境变量 `DATA_BACKEND=cloud` 已保存并重新部署 |
| 写操作永远返回 `[确认码 Cxxx]` 不执行 | 这是 **L1 确认门** 正常工作 | 再发一次 `lab_confirm` 带确认码即可真正写入 |
| 审批/批量卡住超时 | 超时时间仍是 3s | 步骤 3 改 60s |
| 教师查不到数据 | 教师用个人密钥，权限=本人身份 | 正常；教师只能看本人权限内数据，管理员用 `ROBOT_KEY` 可看全部 |
| 控制台「保存」按钮转圈 | 控制台偶发卡 | 改用 `env.local.js` 兜底（见 `上线操作手册.md` 2.2），或刷新重登 |

## 12. 安全红线（务必遵守）

- ❌ 绝不把管理员 `ROBOT_KEY` 发给任何教师（教师用各自个人密钥）。
- ❌ 绝不把 `env.local.js` 明文提交到公开仓库（已 gitignore）。
- ❌ 教师写操作必须经 L1 确认门，连接器不绕过。
- ✅ 密钥可随时在「我的」页吊销，吊销即失效。
- ✅ 机器通道默认 **fail-closed**：`ROBOT_KEY` 未配置且无可解析个人密钥时，外部调用只能走公开只读接口。

## 13. 批量导入清单（Excel → 耗材/工具集合）

无需改小程序、无需逐条手录：把清单 Excel 交给 WorkBuddy，连接器本地解析后整批写入后台。

**前置**：`docsProxy` 已按本文档部署（含第 4 节 SDK 配置）、本机 `mcp.json` 已配 `TCB_*` + 管理员 `ROBOT_KEY`。

**两种导入目标**（通过 `lab_import` 的 `resourceType` 参数切换）：

- `resourceType="material"`（默认）→ 写入 **`materials` 耗材集合**，字段含库存、单位、预警线、类别。
- `resourceType="tool"` → 写入 **`tools` 工具集合**，字段含状态、保管人（工具无库存概念，不写出入库流水）。

**耗材清单列（表头容错，无需严格命名）**：

| 系统字段 | 可接受的表头别名（示例） |
|---------|------------------------|
| `id`（可选，用于更新已有） | 编号 / 物料编码 / 编码 / 设备编号 |
| `name`（必填） | 名称 / 物品名称 / 物料名称 / 品名 |
| `spec` | 规格 / 型号 / 规格型号 |
| `cat` | 类别 / 分类 / 类型 |
| `loc` | 存放位置 / 库位 / 货架 |
| `stock`（期初库存） | 当前库存 / 库存 / 数量 / 期初库存 |
| `unit` | 单位 / 计量单位 |
| `safe` | 预警线 / 安全库存 / 最低库存 |

**工具清单列（表头容错）**：

| 系统字段 | 可接受的表头别名（示例） |
|---------|------------------------|
| `id`（可选，用于更新已有） | 编号 / 工具编号 / 资产编号 / 编码 |
| `name`（必填） | 名称 / 工具名称 / 设备名称 / 品名 |
| `spec` | 规格 / 型号 / 规格型号 |
| `loc` | 存放位置 / 库位 / 货架 |
| `status` | 状态 / 当前状态 / 使用情况（默认「正常」） |
| `holder` | 持有人 / 保管人 / 当前持有人 / 责任人 |

未识别的列会被忽略并在预览中提示；缺 `name` 的行自动跳过。

**操作步骤**：

1. 在 WorkBuddy 对话里说（或调用工具）`lab_import`，传入本地 Excel 绝对路径与目标类型：
   ```
   导入工具清单 D:/清单/工具清单.xlsx        # 默认 resourceType=material
   导入工具清单 D:/清单/工具清单.xlsx → tool  # 或显式 resourceType="tool"
   ```
2. 连接器先**只预览**（dryRun）：返回「共 N 条有效行 + 前 5 条预览 + 未识别列提示」，**不写库**。核对字段映射无误。
3. 确认无误后再次调用 `lab_import` 并设 `dryRun:false` → 连接器返回 **`[确认码 Cxxx]`**（L1 二次确认门）。
4. 回复「确认执行」或调用 `lab_confirm`，云端整批写入：
   - 耗材（`importMaterials`）：按 `id`（优先）→ `name` 匹配已有；命中则更新描述字段并按需校准库存（差额写流水），未命中则新建（自动 `Mxxx` 编号、建档入库流水）。
   - 工具（`importTools`）：按 `id`（→`Txxx`）→ `name` 匹配已有；命中则更新描述字段并记日志，未命中则新建（自动 `Txxx` 编号）。
   - 两者均返回 `{ created, updated, skipped }` 汇总。
