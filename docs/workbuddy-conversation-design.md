# 通过 WorkBuddy 与「实训室管理系统」对话的方案（交互设计）

> 适用前提：已完成 `docs/workbuddy-integration.md` 的技术集成（MCP 连接器 + 云函数 robot 通道 + HTTP 触发）。
> 本文回答的是**使用层问题**：集成就绪后，你（邓老师）如何用自然语言跟系统"对话"，以及这套对话为什么科学、怎么兜底安全。

---

## 一、总体定位（一句话）

WorkBuddy 是系统的**自然语言操作台**：你用中文说话 → 它把意图翻译成后端 `action` 调云函数 → 把结果读回给你。
**它不替代小程序 UI，而是给管理员/教师一个"随口问、顺手办"的快速入口。**

- 小程序 UI：扫码、拍照、现场填表、复杂交互 —— 人在现场用。
- WorkBuddy：随时问数据、口头下指令、审批流快速处理 —— 人在电脑前用。

---

## 二、交互分层模型

对话不是"一句话直达数据库"，而是五层管线，每层职责单一、可独立校验：

```
① 自然语言输入层   你打的字（未来可接语音）
        ↓
② 意图理解层       WorkBuddy LLM：意图识别 + 槽位(slot)抽取
        ↓
③ 工具调度层       MCP 连接器 → docsProxy 云函数（robot 身份，只读白名单）
        ↓
④ 确认与护栏层     白名单拦截 / 写操作二次确认 / 审计留痕
        ↓
⑤ 结果呈现层       表格 / 摘要 / 异常提示 / 来源标注
```

> 关键原则：**自然语言永远不直接拼 SQL 或表达式**，只映射到预定义的 67 个 `action` + 结构化参数。这从根上杜绝注入。

---

## 三、对话能力分级（科学分期，先窄后宽）

| 级别 | 能力 | 风险 | 当前状态 |
|---|---|---|---|
| **L0 只读查询** | 查物料/待审批/报表/实训室概况 | 极低（不改数据） | ✅ 已落地（READ_ACTIONS 白名单） |
| **L1 受控写** | 新建物料、审批、出入库、报修/巡检 | 中（需防误触） | ✅ 已落地（lab_write + lab_confirm 确认门） |
| **L2 主动服务** | 定时日报、逾期预警推送 | 低（只读+通知） | ✅ 已落地（每日 08:20 预警推送自动化） |
| **L3 多轮协作** | 基于上下文追问、批量编排 | 中 | ✅ 已落地（lab_context/lab_forget 会话记忆） |

> 建议严格按 L0→L1→L2 推进。**L0 足够日常"问数据"；L1 才放"办业务"，且必须带确认门。**

## 四、核心交互协议（最关键的四条规定）

### 4.1 意图—槽位模板（给 LLM 一本"字典"）
把高频意图写成模板，LLM 照此抽取参数，避免自由发挥：

| 你说的话（示例） | 意图 | 映射 action | 槽位 |
|---|---|---|---|
| "查一下电阻类物料" | 查物料 | `listMaterials` | `keyword=电阻` |
| "列出待审批" | 查待办 | `pending` | — |
| "L001 实训室的报修和巡检概况" | 实训室概况 | `labOverview` | `labId=L001` |
| "本月耗材消耗 Top5" | 报表 | `usage` | `range=本月` |
| "A 柜有哪些东西" | 按位置查 | `listMaterials` | `loc=A柜` |
| （L1）"新建物料 电阻10k 500个 放 A柜-3" | 建物料 | `addMaterial` | `name/spec/stock/loc` |

### 4.2 歧义消解协议（**不猜测，先反问**）
当槽位不足或命中多义，WorkBuddy **必须反问**，绝不替你拍板：
- 你："查一下螺丝" → 它："匹配到 3 项：内六角螺丝 M3 / 自攻螺丝 / 法兰螺丝，要看哪个？或指定实训室？"
- 你："那个实训室最近咋样" → 它："你说的'那个'是指上次看的 L001 吗？还是让我列出你有权限的实训室？"

### 4.3 写操作确认门（**防误操作的铁律**）
任何非只读 action，走"回显 → 等你确认 → 才执行"三步：
1. **回显**：`将执行：addMaterial(name=电阻10k, spec=1/4W, stock=500, loc=A柜-3)`
2. **等确认**：你必须回 `确认` / `执行` / `y` 才真正调云函数
3. **结果**：返回 `{code:0, id:...}` 并提示"已创建，可在小程序库存页核对"
> 不可逆操作（删除、冲销）**默认拒绝自然语言**，强制走小程序 UI，除非你显式要求并二次确认。

### 4.4 身份与来源透明（审计友好）
每次回显都带来源标注：`（来源：云库 · 操作人：T001·robot）`，让你随时知道"这条数据哪来的、以谁的身份操作的"。

### 4.5 能力边界声明（**不懂就直说**）
超出白名单时明确拒绝并指路，不硬来：
- "批量删除暂不支持自然语言，请在小程序操作"
- "改权限这类管理动作请走小程序后台"

## 五、典型对话示例（5 个场景）

**场景1 · 只读查询（L0）**
> 你：显示系统运行态
> WB：`lab_diag` → 后端=cloud，物料 4 条，工具 4 条，待审批 0。（来源：云库 · robot）

**场景2 · 含糊意图消解（4.2）**
> 你：查一下示波器
> WB：匹配到 2 项（① 示波器 CH1 无波形-报修单 R12；② 示波器设备-库存 M05）。要看报修详情还是库存信息？

**场景3 · 受控写+确认（L1，4.3）**
> 你：新建物料 电阻10k 500个 放 A柜-3
> WB：将执行 `addMaterial(name=电阻10k, spec=1/4W, stock=500, loc=A柜-3)`，确认吗？
> 你：确认
> WB：`{code:0, id:M新}` 已创建，可在小程序库存页核对。（来源：云库 · T001·robot）

**场景4 · 上下文续接（L3 已落地）**
> 你：查一下 L001 实训室的报修
> WB：`lab_query(listRepairs, {labId:L001})` → 返回 3 条；连接器记住锚点 `实训室=L001`。
> 你：那它的巡检呢？
> WB：先 `lab_context` 取到锚点 `实训室=L001` → `lab_query(listInspections, {labId:L001})` → 返回 2 条逾期。
> （话题切换或隐私顾虑时 `lab_forget` 清掉记忆，避免沿用旧锚点。）

**场景5 · 边界拒绝（4.5）**
> 你：把张老师的账号删了
> WB：删除用户属于不可逆管理动作，自然语言不支持。请在小程序「用户管理」操作，或我先帮你查出该账号信息核对。

## 六、安全与治理

- **最小权限**：robot 身份先以 `T001`(super) 跑通；正式期建议降为某教师工号，只读+其权限内写，多人分管更稳。
- **审计**：所有 robot 操作以 `ROBOT_ACTOR_ID` 身份落 `logs`/`access`，与微信端用户区分。
- **防注入**：自然语言 → 预定义 action + 结构化参数，绝不拼接表达式。
- **Fail-closed**：`ROBOT_KEY` 未配 → 外部调用只能走公开接口，拿不到业务数据。
- **可逆优先**：写操作依赖后端既有 `withWriteIdem`（幂等），避免重复提交。

## 七、落地路线图

- **Phase 1（已落地）**：L0 只读查询上线，先验证 NL→action 映射准不准。
- **Phase 2（已落地）**：开放 L1 受控写 + 确认门（lab_write/lab_confirm，白名单覆盖物料/审批/出入库/报修/巡检）。
- **Phase 3（已落地）**：L2 主动服务——接 WorkBuddy 自动化，每日 08:20 推送耗材预警/逾期巡检。
- **Phase 4（已落地）**：语音输入（复用 WorkBuddy 自带语音）+ 多轮记忆编排（lab_context/lab_forget 会话锚点，LLM 据此消解模糊追问）。

---

## 八、与小程序 UI 的分工（一句口诀）

> **WorkBuddy 管"嘴"：问数据、下指令、批流程；**
> **小程序管"手"：扫码、拍照、填表、现场操作。**

两者共享同一套云端数据（CloudBase），互不替代、互补增效。
